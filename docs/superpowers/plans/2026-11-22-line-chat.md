# LINE Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** LINE users can tap "ถามต่อ" under a result and chat about it (questions free, one free re-search), with the same rules as the web app.

**Architecture:** The chat rules move from the web route into `createChat()` in `src/chat.js`. `server.js` makes one instance and gives it to the web app and to the bot, so the one-at-a-time guard is shared. The bot keeps an in-memory map of LINE user id to `{ jobId, until }` for its chat mode.

**Tech Stack:** Node 22 (`node:test`), LINE Messaging API via `src/line.js`.

**Spec:** `docs/superpowers/specs/2026-11-22-line-chat-design.md`

## Global Constraints

- Chat only on done/refunded/refund_review jobs; text 1–500 characters; at most 10 questions per job; one question at a time per job; the daily cost cap applies. Errors: `status`, `text`, `limit`, `busy`, `chat_busy`.
- Chat mode lasts 10 minutes after the last message or tap. The commands "เครดิต", "ผลล่าสุด" and "โอนแล้ว" work as before inside chat mode.
- Chat answers go by reply; if the reply fails, push.
- Buttons: "ถามต่อ" uses postback `ask:<jobId>`, "งานใหม่" uses `new:0`, and re-search cards use the existing `start:<id>`. A ฿0 job shows only "ถามต่อ".
- Strip `**` from Smith's chat text in LINE. No commits.

## Review Focus

1. A message that is really a new job, typed in chat mode: it goes to the chat, where "งานใหม่" or the timeout gets the user out (tested: งานใหม่, timeout).
2. Two LINE messages in quick succession: the second gets "Smith กำลังตอบคำถามก่อนหน้า" and is not charged a question (tested through the shared guard).
3. Tapping "ถามต่อ" on someone else's job id, or on a failed job: refused (tested).
4. The reply token expiring while the model answers: the answer is pushed instead (tested with a reply that throws).
5. Existing web chat behaviour is unchanged after the move (the existing web tests).
